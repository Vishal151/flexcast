# Journal

One entry per stage: what was built, what surprised us, open questions.

## Stage 0 — Explore the data
- Built `scripts/explore_api.py` and `scripts/record_fixtures.py` over one shared request list, plus a fixture manifest for respx and mock_upstream. Recorded 26 responses (stored as indented JSON for reviewable diffs, 5.4 MB) for a normal day and both 2025 DST days. Every SPEC §2 Elexon path exists in the live OpenAPI spec.
- Surprises: WINDFOR is hourly with 8 vintages/day on a schedule that is neither UTC- nor London-fixed. NDF publish-window queries are capped at 1 day. MID `from`/`to` are instants, not dates. N2EX MID drops periods on the autumn DST day. My own hand-written Agile window was an hour off on the spring DST day, which is the case for deriving windows from London dates in code.
- Open: does the system-prices endpoint expose settlement-run revisions (`createdDateTime` is ~D+1)? How much of the target day does the latest NDF vintage before D-1 09:00 actually cover? That's the Check yourself question, and it may push decision time or feature design.

## Stage 1 — Core library, local only
- Built config (env-only), fsspec storage (atomic writes), a settlement helper checked against Elexon's own mapping for 144 real periods, Elexon/Octopus clients (retry/backoff, chunking to the 1-day/7-day caps, pydantic validation that also checks settlement date/period against start_time), idempotent ingest (merge on natural key, deterministic Parquet, rejects kept in `rejects/`) and the battery MILP (PuLP + HiGHS). Backfilled 730 days × 6 datasets (40 MB) in ~3.5 min with no failures; a live re-ingest is byte-identical.
- Surprises: PuLP 4 no longer bundles CBC and changed its API (`prob.add_variable`, `LpSolveStatus`), so we added `highspy`. `AGILE-BB-*` is the Bulb-branded Agile, not business. With perfect foresight on system prices a 10 kWh battery makes £278/yr. Degradation is the biggest lever (£656/yr at 0p/kWh vs £278 at 2p). 90%→80% efficiency costs about 20% (£278→£221). Agile gives £648/yr: its retail formula amplifies wholesale spreads and adds a 16:00–19:00 uplift, so it's not a market price.
- MILP vs LP: the binary removes simultaneous charge/discharge (39 of 48 periods in the relaxed LP at −£1000/MWh) but only changes £ by 2p there. The battery can still "earn from losses" by alternating periods, which is physically allowed.
- Open: the 2p/kWh degradation default needs a defensible source before Stage 2 results; Agile export would be paid at the Outgoing rate, so the symmetric-price Agile number overstates value.

## Stage 2 — Forecasting and backtest, local only
- Built `history.py` (the only route from stored data to features; every row has `available_at`), point-in-time `features.py` (23 features, NDF stitched per period, London-clock-time lags), NaiveLastDay / SeasonalNaive / LGBMQuantile behind one interface with text-file serialisation, and a rolling-origin backtest that keeps forecasting and £ valuation separate. Leakage test = poison everything available at/after the decision (features must not change) + per-source provenance + pinned availability rules.
- Result (2025-10-20..2026-10-19, 2p/kWh): perfect £271/yr; LightGBM £33/yr (12% of perfect, MAE 30.6); naive −£149, seasonal −£155 (MAE 44–45). The imbalance price is so noisy (D-2 correlation 0.07) that copying a past day trades on noise and loses money, so "idle = £0" is the real bar, not naive.
- Surprises: real-time system prices publish ~48 min after period start, but the endpoint returns the latest revision with its own (D+1) timestamp, so the historical series is revised values (caveat in results). Mutation testing showed the poisoning test can't catch a *wrong availability rule* (the poison moves with it), so the rules got their own test. PuLP→HiGHS last stage, LightGBM→libomp this stage: native deps will matter in the Dockerfile (`libgomp1`).
- Open: a risk-aware schedule (only trade when the p10/p90 spread clears losses + degradation) looks like the biggest lever for £, bigger than a better p50. Degradation cost is decisive (LightGBM £174/yr at 0p vs £3 at 4p).
- Stage 2b, risk-aware scheduling: plan buying at p50 + α(p90 − p50) and selling at p50 − α(p50 − p10), with α chosen on the 6 months before the test window. The hypothesis was wrong: α = 0 won on validation (£24.6/yr vs £23.0 at 0.25 and £0 at 1) and on the test window in hindsight too. Reason: LightGBM's p50 is already shrunk towards the mean (median forecast daily spread £68/MWh vs £122 actual; trades 76% of days, 11.7 kWh/day vs 31). Its p10–p90 band (£77) is wider than its typical spread, so any α > 0 counts the same uncertainty twice. The losing naive baselines have real-sized spreads at the wrong times and no uncertainty band; that's where an uncertainty gate would help.

## Stage 3 — Containerise and emulate GCP locally
- Built a multi-stage Dockerfile (uv builder, slim runtime, libgomp1, uid 10001, `ENTRYPOINT flexcast`), `compose.yaml` (fake-gcs-server, bucket init, upstream-mock replaying the fixture manifest, api, ingest/train/plan jobs with per-job entrypoints), `flexcast train|plan|serve`, a read-only FastAPI (`/health`, `/schedule`, `/forecast`, `/metrics`), and 13 integration tests (ingest→train→plan through containers, byte-identical re-ingest through the real GCS client, API contract on a non-default PORT, failed upstream → non-zero exit). From an empty Docker cache, `make up && make itest` passes in 77 s.
- Emulator vs real GCS (cover in the Stage 5 smoke test): (1) gcsfs 2026.10 enables an experimental zonal/HNS client by default that probes buckets over gRPC; the emulator can't answer, so every call hung for 60 s. Disabled with `GCSFS_EXPERIMENTAL_ZB_HNS_SUPPORT=false` in every profile. (2) fake-gcs doesn't implement `moveTo`; my temp-file-then-rename write fell back to copy/delete and left stray objects. Replaced with fsspec `autocommit=False` + `commit()`, which is atomic on both local disk and GCS with no branching. (3) fake-gcs hands out resumable-upload URLs at `0.0.0.0` unless told `-external-url http://gcs:4443`. (4) Emulator needs `FSSPEC_GCS_TOKEN=anon`; real GCP uses ADC.
- Other surprises: `docker compose run <svc> <args>` *replaces* the service's command, so job subcommands live in `entrypoint`. `/metrics` crashed on an empty bucket (a fresh deployment): History.load now handles missing datasets. Image is 207 MB compressed but 654 MB on disk (pyarrow + scipy + pandas + numpy ≈ 400 MB); matplotlib moved to an optional `report` group and third-party test suites are stripped.
- Open: SPEC's "image < 500 MB" doesn't say compressed vs on-disk; `make itest` needs uv on the host as well as Docker.
